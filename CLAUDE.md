## What this is

Web admin panel for SST Prevención, in Spanish, styled per the Bauhaus design system (`../stitch_.../bauhaus/DESIGN.md`; tokens in `src/index.css` `@theme`, mirroring `../mobile/src/theme/tokens.ts`). It talks to the same Nest API as the app with the same accounts. `base` is `/panel/`: in production Caddy serves `dist/` from `../../deploy/panel.Dockerfile` and proxies everything else to the API, so `/api` is same-origin (`VITE_API_URL` overrides it).

**Security lives in the backend.** The panel only hides what a profile can't use: `ADMINISTRADOR` sees everything (plus Clasificaciones and creating/deactivating companies), `ADMIN_EMPRESA` manages users/areas/positions of its companies, and `USUARIO` only gets Inicio and Archivo with its own records. Never filter data client-side as a substitute for a backend check.

## Layout

- `src/api.ts`: the only module that knows routes and the backend's Spanish entities; 401 calls the session's handler.
- `src/session.tsx`: `SessionProvider` (token in localStorage), `useSession()`, `useYo()` (user guaranteed, below `Layout`).
- `src/layout.tsx`: sidebar by profile, terms-acceptance gate, `SoloGestor` route guard.
- `src/ui.tsx`: components only (Btn, Card, Field, Select, Check, Modal, Tag, RiskTag, Toasts…). `src/lib.ts`: non-component helpers (`cx`, `fecha`, `toast`, `useCarga`, `TIPO`, `NIVEL_MATRIZ`), kept apart for Vite fast refresh.
- `src/pages/`: Inicio, Empresas/EmpresaDetalle (data, logo, areas, positions, members), Usuarios/UsuarioDetalle, Clasificaciones, Archivo (one folder per company) → ArchivoEmpresa (grouped by month, filters) → Registro (printable detail of reports, ergonomics, matrices, permits and accident reports; the paper-format PDFs are still generated by the app's `pdf.ts`).
